## 2. قاعدة البيانات والترحيلات

- [ ] تشغيل `database/apply-migrations.ps1` ينجح ويظهر `Applied: 0` (كل الترحيلات مطبّقة).
- [ ] `SELECT version FROM schema_version ORDER BY version;` يعرض **V001–V022** بلا فجوات.
- [ ] checksum كل ترحيل مطابق (السكربت يرفض غير المطابق).
- [ ] نسخة احتياطية كاملة حديثة موجودة + ملف `.sha256` (راجع القسم 4).
- [ ] مستخدم التطبيق `smart_hospital_app` يملك DML فقط، ولا يملك DDL/GRANT.
- [ ] حساب الترحيل منفصل عن حساب التطبيق.

- [ ] حسابات المستخدمين الإنتاجية أُنشئت بكلمات مرور قوية و`must_change_password=TRUE`.
- [ ] سياسة الاحتفاظ بالبيانات والتدقيق محدّدة ومطبّقة.

## 3. الأمان (تقني + إعدادات)

- [ ] HTTPS مفعّل بشهادة من **CA موثوق** (ليست self-signed).
- [ ] `SMART_HOSPITAL_FORCE_HTTPS=true` أو `-Dsmarthospital.forceHttps=true` مضبوط.
- [ ] TLS 1.2+ فقط، والخادم يرفض TLS 1.0/1.1.
- [ ] `sslMode=VERIFY_IDENTITY` في اتصال MySQL، وليس `DISABLED`.
- [ ] كلمة مرور MySQL في alias/خزنة أسرار، وليست نصاً صريحاً.
- [ ] `SMART_HOSPITAL_ENFORCE_PASSWORD_ROTATION=true` مضبوط، وكل الحسابات غيّرت كلمات المرور الإجبارية.
- [ ] شاشة `/change-password` مُختبرة: الدخول ينقل إليها، والتغيير يُبطل الجلسات ويعيد إلى تسجيل الدخول.
- [ ] MFA (TOTP) مفعّل للمسؤولين والأطباء: مفتاح AES موفّر، والأدوار الملزمة محدّدة عبر `smarthospital.mfa.requiredRoles`، وكل الحسابات الملزمة أكملت التسجيل.
- [ ] مفتاح MFA منسوخ احتياطياً خارج قاعدة البيانات (خزنة أسرار) ومُوثّق في خطة DR.
- [ ] رموز الاسترداد سُلّمت للموظفين بأمان، وإجراء إعادة التعيين الإدارية (`PATCH /admin/accounts/{id}/mfa-reset`) مُختبر.
- [ ] `GET /api/v1/security/metrics` يعمل لـ`HOSPITAL_ADMIN` ويعيد 403 لغيره.
- [ ] `lockedAccounts` و`accountsPendingPasswordChange` تحت المراقبة.
- [ ] `GET /api/v1/audit-logs/integrity` يعيد `chainIntact=true`.
- [ ] `scripts/verify-audit-chain.ps1` يعيد `AUDIT_CHAIN_OK`.
- [ ] لا توجد حسابات تجريبية بكلمة `Demo@2026`.
- [ ] مراجعة صلاحيات نهائية: كل مستخدم على الحد الأدنى الضروري.
- [ ] الجلسات القديمة أُبطلت (`user_sessions` نظيفة) قبل الإطلاق.
- [ ] اختبار اختراق مستقل مكتمل — **مؤسسي**.
- [ ] مراجعة كود أمني مستقلة مكتملة — **مؤسسي**.

## 4. النسخ الاحتياطي والتعافي

- [ ] `scripts/backup-database.ps1` نُفّذ على قاعدة الإنتاج → `BACKUP_OK`.
- [ ] ملف النسخة + `.sha256` منسوخان إلى تخزين **خارج الخادم** ومشفّر.
- [ ] استعادة اختبارية إلى قاعدة منفصلة نجحت → `RESTORE_OK`.
- [ ] بعد الاستعادة: `AUDIT_CHAIN_OK` و`smoke-test` 56/56.
- [ ] جدولة النسخ اليومية مفعّلة (Task Scheduler/cron) مع تنبيه عند الفشل.
- [ ] النسخ الساعية (binlog) مفعّلة إن كان RPO ≤ 15 دقيقة مطلوباً.
- [ ] خطة DR موثّقة ومُختبرة، وRTO/RPO معتمدان.
- [ ] صلاحية الوصول لمجلد النسخ مقصورة على DBA.
