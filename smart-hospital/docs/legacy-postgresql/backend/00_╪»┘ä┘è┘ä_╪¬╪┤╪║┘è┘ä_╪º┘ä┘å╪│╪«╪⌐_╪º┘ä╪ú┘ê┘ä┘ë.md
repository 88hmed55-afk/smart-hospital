# دليل تشغيل أول نسخة من Backend — Smart Hospital

هذه الوثيقة تشرح تجهيز وتشغيل النواة الأولى على Windows. لا تستخدم بيانات مرضى حقيقية؛ استخدم بيانات تجريبية فقط.

## أولاً: ما الذي تحتاج إلى تثبيته؟

1. **JDK 21** أو أحدث.
2. **Maven 3.9.16** أو أحدث.
3. **PostgreSQL 16** أو أحدث، مع pgAdmin أو أداة `psql`.
4. **GlassFish 8.0.5 — Jakarta EE 11 Full Platform**، وليس Web Profile.
5. برنامج تشغيل PostgreSQL JDBC المتوافق.

روابط رسمية:
- GlassFish: https://glassfish.org/download
- GlassFish Release Notes: https://glassfish.org/docs/latest/release-notes.html
- PostgreSQL JDBC: https://jdbc.postgresql.org/download/

## ثانياً: إنشاء قاعدة البيانات

افتح pgAdmin، اتصل بمستخدم PostgreSQL الإداري، ثم نفّذ مرة واحدة في Query Tool:

```sql
CREATE ROLE smart_hospital LOGIN PASSWORD 'ضع_كلمة_مرور_قوية_هنا';
CREATE DATABASE smart_hospital OWNER smart_hospital;
```

استخدم كلمة مرور قوية. لا تشاركها في المحادثة أو في ملفات المشروع.

## ثالثاً: تطبيق الجداول والبيانات التجريبية

افتح PowerShell داخل المجلد الرئيسي للمشروع `smart-hospital-foundation`، وليس داخل مجلد `backend`، ثم نفّذ:

```powershell
.\database\apply-local.ps1 -Database smart_hospital -Username smart_hospital
```

سيطلب PostgreSQL كلمة مرور المستخدم. السكربت ينفذ بالترتيب:

- V001: الجداول الأساسية.
- V002: التنويم والمشتريات والتحليلات والمحاسبة.
- V003: صلاحيات وصول المرضى على مستوى الفرع.
- فحص بنية الجداول بعد V002 وV003.
- إدخال فرع وأقسام وطبيب وموظف استقبال تجريبيين.
- ربط حسابات GlassFish المحلية بحسابات المستشفى والأدوار والفروع.
- فحص وجود حسابات العرض وربطها بالأدوار والفروع الافتراضية.

**تحذير:** السكربت مخصص لقاعدة بيانات جديدة فارغة فقط. لا تشغله مرة ثانية على قاعدة سبق تطبيق migrations عليها.

إذا كنت قد طبقت نسخة v0.3 السابقة (V001 وV002) بالفعل، فلا تعِد إنشاء القاعدة ولا تشغّل سكربت التثبيت الكامل. استخدم بدلاً منه:

```powershell
.\database\upgrade-v0.3-to-v0.4.ps1 -Database smart_hospital -Username smart_hospital
```

هذا التحديث يضيف V003 وبيانات حسابات العرض فقط، ويتحقق من أن قاعدة البيانات في حالة v0.3 قبل إجراء أي تغيير.

## رابعاً: ربط PostgreSQL مع GlassFish

1. انسخ ملف PostgreSQL JDBC Driver إلى مجلد:

   `glassfish\domains\domain1\lib`

2. أعد تشغيل GlassFish domain.
3. شغّل `asadmin.bat` من مجلد `glassfish\bin` وأنشئ Connection Pool:

```powershell
.\asadmin.bat create-jdbc-connection-pool --datasourceclassname org.postgresql.ds.PGSimpleDataSource --restype javax.sql.DataSource --property "user=smart_hospital:password=CHANGE_ME:databaseName=smart_hospital:serverName=localhost:portNumber=5432" SmartHospitalPool
```

4. أنشئ مورد JNDI:

```powershell
.\asadmin.bat create-jdbc-resource --connectionpoolid SmartHospitalPool jdbc/SmartHospitalDS
.\asadmin.bat ping-connection-pool SmartHospitalPool
```

استبدل `CHANGE_ME` بكلمة مرور قاعدة البيانات. لأن `:` فاصل بين خصائص GlassFish، لا تستخدم نقطتين رأسيتين في كلمة المرور بهذا المثال إلا إذا عرفت طريقة تهريبهما.

## خامساً: إنشاء مستخدمين تجريبيين في GlassFish

تأكد أن GlassFish domain يعمل، ثم نفذ من `glassfish\bin`:

```powershell
.\asadmin.bat create-file-user --groups HOSPITAL_ADMIN hospitaladmin
.\asadmin.bat create-file-user --groups RECEPTIONIST receptionist1
.\asadmin.bat create-file-user --groups DOCTOR doctor1
```

سيطلب منك الخادم كلمات المرور. هذه الحسابات تُستخدم للمصادقة المحلية داخل GlassFish `file` realm. بعد نجاح المصادقة، يطابق Backend اسم المستخدم مع جدول `hospital.user_accounts` ويتحقق من حالة الحساب وفروعه، كما يطبق صلاحيات الدور عبر GlassFish. حقل `password_hash` في الحسابات التجريبية يحتوي علامة `GLASSFISH_FILE_REALM_ONLY` وليس كلمة مرور أو hash صالحاً؛ لا تستخدم حسابات العرض هذه للمصادقة الإنتاجية.

## سادساً: بناء Backend ونشره

افتح PowerShell داخل مجلد `backend`:

```powershell
mvn clean package
```

عند نجاح البناء، سيُنشأ:

`backend\target\smart-hospital-api.war`

انشر الملف من مجلد `glassfish\bin`:

```powershell
.\asadmin.bat deploy "C:\المسار\إلى\المشروع\backend\target\smart-hospital-api.war"
```

استبدل المسار بمسار المشروع الحقيقي على جهازك.

## سابعاً: اختبار أول endpoint

افتح المتصفح على:

`http://localhost:8080/smart-hospital-api/api/v1/health`

المفترض أن ترى حالة `UP`. هذا الاختبار يؤكد استجابة التطبيق فقط، ولا يؤكد جاهزية قاعدة البيانات أو JMS.

لاختبار بقية المسارات، راجع `docs/backend/02_api_examples.md` و`docs/backend/openapi-v1.yaml`.

## حدود النسخة الحالية

هذه نواة أكاديمية قابلة للتطوير، وليست نظاماً جاهزاً للتشغيل السريري. تم ربط اسم مستخدم GlassFish بحساب مستشفى نشط في قاعدة البيانات، وتطبيق نطاق الوصول على الفروع وملفات المرضى. لكن لا تزال هناك حاجة إلى إكمال مصادقة إنتاجية آمنة، وصلاحيات أدق على مستوى القسم وعلاقة الرعاية، وتسجيل محاولات الوصول المرفوضة، واختبارات تكامل فعلية على GlassFish وPostgreSQL، قبل السماح ببيانات مرضى حقيقية.
