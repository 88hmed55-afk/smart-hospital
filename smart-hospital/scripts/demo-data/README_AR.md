# البيانات التجريبية — مولّد ستة أشهر

مولّد بيانات اصطناعية لمنصة **Smart Hospital** يبني تاريخاً تشغيلياً ومالياً متكاملاً يمتد **183 يوماً في الماضي** إضافة إلى **30 يوماً من الحجوزات المستقبلية**، بهدف اختبار التقارير والاتجاهات والفواتير والمخزون وسلسلة التدقيق على بيانات كثيفة قريبة من الواقع.

- الملفات: `scripts/demo-data/seed.js` (التوليد) و`scripts/demo-data/verify.js` (التحقق) و`scripts/demo-data/lib/*.js` (الوحدات).
- لا يستخدم المولّد أي حزمة خارجية، فقط وحدات Node.js المدمجة وبرنامج `mysql` الرسمي.
- لا يعدّل أي صف موجود ولا يحذف شيئاً؛ كل ما يفعله هو `INSERT` لصفوف جديدة.

---

## 1. المتطلبات

| العنصر | المطلوب |
|---|---|
| Node.js | 18 أو أحدث (تم التشغيل على 26.4.0) |
| MySQL | 8.0، قاعدة `hospital`، مع `--login-path` معدّ مسبقاً |
| مخطط القاعدة | بعد تطبيق الترحيلات **V001–V022** |
| صلاحية الحساب | `INSERT` على جداول الرعاية والمخزون والفوترة والمحاسبة والتحليلات |

مسار عميل MySQL الافتراضي هو `C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe`، ويمكن تجاوزه:

```powershell
$env:SMART_HOSPITAL_MYSQL = 'D:\mysql\bin\mysql.exe'
$env:SMART_HOSPITAL_LOGIN_PATH = 'smart-hospital-local'
```

## 2. الاستخدام

من جذر المستودع:

```powershell
# المجموعة الافتراضية (220 مريضاً، 140 تنويماً، 16 تنويماً نشطاً)
node scripts/demo-data/seed.js

# حجم أكبر أو أصغر
node scripts/demo-data/seed.js --patients 260 --admissions 160 --active-admissions 20

# بلا مخرجات تفصيلية
node scripts/demo-data/seed.js --quiet

# توليد ملفات SQL بدل التنفيذ المباشر
node scripts/demo-data/seed.js --sql-out C:\temp\demo-sql
```

### الخيارات

| الخيار | الافتراضي | المعنى |
|---|---|---|
| `--patients <n>` | `220` | عدد المرضى الجدد |
| `--admissions <n>` | `140` | إجمالي حالات التنويم (منها النشطة) |
| `--active-admissions <n>` | `16` | حالات التنويم النشطة الآن (تشغل أسرة فعلية) |
| `--login-path <name>` | `smart-hospital-local` | مسار تسجيل الدخول في `mysql` |
| `--mysql <path>` | المسار أعلاه | مسار برنامج `mysql` |
| `--sql-out <dir>` | — | كتابة أوامر كل مرحلة في ملفات `.sql` بدل تنفيذها مباشرةً |
| `--quiet` | — | إخفاء سجل التقدم |

> `--sql-out` يكتب ملفات SQL فقط، **ولا ينفّذها**. لتطبيقها لاحقاً استخدم `mysql ... < phase.sql` مع `--default-character-set=utf8mb4`.

تشغيل افتراضي واحد ينتج (الأرقام الفعلية من تشغيل موثّق في 11 نوفمبر 2026؛ تتفاوت قليلاً بين التشغيلات):

|---|---|

| المواعيد | 2,139 موعداً (183 يوماً ماضياً + 30 يوماً مستقبلاً) |
| الزيارات السريرية | 1,783 زيارة (خارجية وطوارئ وتنويم) |

| المخزون والمشتريات | 133 دفعة، 32 أمر شراء، 26 إشعار استلام، 2,168 حركة مخزون، 90 رصيداً |
| الفواتير والمدفوعات | 1,558 فاتورة، 3,430 بنداً، 1,498 دفعة |

التوزيع الشهري للمقبوضات مُصمَّم ليكون غير متساوٍ (اتجاه صاعد مع مواسم)، ويغطي كل شهر من نافذة الستة أشهر. يتولّى `verify.js` إثبات ذلك.

### تكامل البيانات

المولّد لا يكتب صفوفاً معزولة، بل يبني سلاسل مترابطة:

- كل زيارة مكتملة تُنتج فاتورة من `service_catalog` (كما يفعل `BillingService`)، وكل دفعة ترتبط بفاتورة، وكل فاتورة/دفعة تُنتج قيداً محاسبياً متوازناً بحالة `POSTED`.
- كل صرف دوائي يخصم من دفعات مخزون حقيقية بسياسة **FEFO**، ورصيد المخزون مشتق من سجل الحركات نفسه، ولا يصبح أي رصيد سالباً في أي لحظة.
- كل نتيجة مختبر تُراجَع وتُعتمد بترتيب زمني صحيح، ولا تُعتمد قبل سحب العينة.
- كل إشعار مرتبط بحدث `message_outbox` حقيقي، وأحداث المختبر تُنشر عبر `PUBLISHED` لتجنّب JMS أثناء البذر.

## 4. المعرّفات المحجوزة

كل صف يولّده المولّد يحمل بادئة معرّف مميزة، ما يجعل استهدافه أو حذفه لاحقاً آمناً ومحدداً:

| البادئة | الاستخدام |
|---|---|
| `deadbeef-0000-4000-8000-<12 hex>` | الصفوف المعاملاتية: المرضى، المواعيد، الزيارات، الفواتير، القيود، الحركات، اللقطات… |
| `feedface-0000-4000-8000-<12 hex>` | البيانات المرجعية: الموظفون، الأدوية، الخدمات، الأسر، الموردون… |

لا يستخدم المولّد أي بادئة أخرى، ولا يمسّ الجداول التالية إطلاقاً:

- `user_accounts` و`user_sessions` (الهوية والجلسات),
- `audit_logs` و`audit_chain_state` (سلسلة التدقيق append-only),
- أي صف موجود مسبقاً في القاعدة (لا `UPDATE` ولا `DELETE`).

يمكن التحقق من ذلك في أي وقت:

```sql
SELECT COUNT(*) FROM hospital.audit_logs
WHERE resource_id LIKE 'deadbeef%' OR resource_id LIKE 'feedface%';  -- صفر بعد البذر مباشرةً
```

> بعد استخدام التطبيق قد تُضاف صفوف تدقيق حقيقية تشير إلى مرضى أو تنويمات تجريبية (فاعل التطبيق مسجّل في `actor_user_id`). هذا سلوك طبيعي ولا يعني أن المولّد كتب في `audit_logs`؛ المولّد لا يكتب فيها إطلاقاً، ولهذا يستثني فحصُ `verify.js` الصفوفَ التي لها فاعل.

## 5. التحقق

```powershell
node scripts/demo-data/verify.js
```

يفحص **83** شرطاً في تسع مجموعات: حجم البيانات، النافذة الزمنية، حساب الفواتير، المحاسبة والتوازن، المخزون عبر الزمن، المختبر، النشاط السريري، التحليلات والإشعارات، ونظافة المعرّفات.

```
VERIFY OK — 83 checks passed, 0 failed.
```

أي فشل يطبع اسم الفحص والعدد المخالف مع أمر SQL المقابل، ويُنهي العملية بالرمز 1 — وهو ما يجعل السكربت صالحاً للاستخدام في CI.

## 6. قبل التشغيل: مخطط القاعدة

المولّد يحتاج مخططاً يحتوي:

1. **V021** — إصلاح قيدَي JSON (`ck_metric_dimensions_object` و`ck_decision_card_json`) لمقارنة `JSON_TYPE()` بالأحرف الكبيرة (`'OBJECT'`/`'ARRAY'`). بدون هذا الإصلاح ترفض القاعدة كل لقطة مؤشر وكل بطاقة قرار.
2. **V022** — عمود `purchase_order_items.received_quantity` (يضيفه V009 في المسار المرقّم، لكن قواعد البيانات المبنية من `01_schema.sql` القديم قد تفتقده). بدون هذا العمود يفشل `/procurement/purchase-orders` بخطأ `Unknown column`.

```powershell
cd .\database
powershell -ExecutionPolicy Bypass -File .\apply-migrations.ps1 -LoginPath smart-hospital-local
```

> تحقّق من العمود يدوياً عند الشك:
> `SELECT COUNT(*) FROM information_schema.COLUMNS WHERE TABLE_SCHEMA='hospital' AND TABLE_NAME='purchase_order_items' AND COLUMN_NAME='received_quantity';`

## 7. إعادة البذر

**لا توجد إعادة بذر آمنة فوق بيانات موجودة.** يحرس `seed.js` نفسه: إذا وجد أي صف ببادئة `deadbeef` أو `feedface` في `patients` أو `staff_members` يتوقف فوراً بالرسالة:

```
ABORT: the demo dataset is already present ... Restore the pre-seed database backup before seeding again.
```

الإجراء الصحيح:

```powershell
# 1) استعادة النسخة النظيفة السابقة للبذر (MySQL client، وليس PowerShell redirection)
cmd /c "\"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe\" --login-path=smart-hospital-local --default-character-set=utf8mb4 hospital < \"C:\backups\hospital-pre-demo.sql\""

# 2) التأكد من وجود إصلاحَي المخطط
#    V021: قيدا JSON بالأحرف الكبيرة
#    V022: purchase_order_items.received_quantity
#    (طبّق الترحيلات إن لم تكن مطبّقة)

# 3) إعادة التوليد ثم التحقق
cd C:\path\to\smart-hospital
node scripts/demo-data/seed.js
node scripts/demo-data/verify.js
```

> **مهم:** النسخة الاحتياطية النظيفة لهذه البيئة (`hospital-pre-demo-clean.sql`) بُنيت قبل V021/V022، لذا يجب تطبيق الإصلاحين بعد كل استعادة وقبل البذر. الأسهل هو استخدام `database\apply-migrations.ps1` إن كانت جداول `schema_version` متوافقة، وإلا فطبّق أوامر V021/V022 يدوياً.

## 8. ماذا تعني «اليوم» في لوحة القيادة؟

- جميع الطوابع الزمنية تُخزَّن بـUTC وتُعرض بتوقيت الفرع **UTC+3**.
- البذر يعتمد لحظة التشغيل `NOW`؛ كل صف معاملاتي يقع في الماضي، والمواعيد غير المنتهية تصبح حجوزات مستقبلية.
- عند التشغيل بعد منتصف الليل بقليل (كما في هذه البيئة) تكون مؤشرات **«اليوم»** في لوحة القيادة قريبة من الصفر (زيارات بدأت اليوم، إيراد اليوم، متوسط المختبر)، بينما تظهر مواعيد اليوم وحالات التنويم النشطة وعناصر المختبر المعلّقة بأرقام حقيقية. هذا سلوك متوقع في نظام تشغيلي يومي، وليس نقصاً في البيانات: أعد التشغيل خلال ساعات العمل إن أردت لوحة «اليوم» ممتلئة.
- التقارير والاتجاهات والتحليلات لا تتأثر، لأنها تعتمد نافذة الستة أشهر.

## 9. استكشاف الأخطاء

| العرض | السبب والحل |
|---|---|
| `MySQL query failed` | تعذّر تنفيذ استعلام عبر `mysql`. تحقق من `--login-path` ومن تشغيل خدمة MySQL.  |
| `Check constraint 'ck_metric_dimensions_object' is violated` | لم يُطبَّق **V021**. طبّقه ثم أعد المحاولة. |
| `Unknown column 'received_quantity'` | لم يُطبَّق **V022**. طبّقه ثم أعد النشر. |
| `ABORT: the demo dataset is already present` | استعد النسخة النظيفة (القسم 7). |
| خروج بالرمز 1 مع نجاح العملية | سلوك معروف لـPowerShell مع `mysql` عند طباعة تحذيرات إلى `stderr`؛ تحقق من السجل الفعلي ومن `verify.js`. |
| مسارات عربية مشوّهة أو `Set-Location` يفشل | شغّل الأوامر من نافذة PowerShell افتُتحت على مجلد المشروع، وتجنّب تمرير المسار العربي كوسيط؛ استخدم `cd` داخل الصدفة. |
| ملف SQL تالف بعد `>` | PowerShell 5.1 يكتب UTF-16. استخدم `cmd /c "... < file"` أو مرّر المحتوى عبر `input` كما يفعل `lib/db.js`. |
