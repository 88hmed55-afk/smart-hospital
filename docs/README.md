# Smart Hospital — حزمة التخطيط الاحترافية

> **النسخة:** 1.0 — خطة تأسيسية قابلة للتنفيذ
> **التاريخ:** 2026-11-09
> **الهدف:** تحويل فكرة Smart Hospital إلى مشروع مؤسسي قابل للتشغيل والاختبار والدفاع الأكاديمي، باستخدام Java EE / Jakarta EE وGlassFish وPostgreSQL وReact.

---

## لماذا هذه الحزمة؟

الفكرة الأصلية قوية، لكن المشروع المؤسسي لا ينجح بالوحدات والشاشات فقط. ينجح عندما تكون **العمليات الحرجة مضبوطة** (صرف دواء، نتيجة مختبر، سرير، دفعة مالية)، و**الصلاحيات قابلة للإثبات**، و**الأخطاء والتزامن مُختبرة**، و**الذكاء التشغيلي قابل للتفسير**.

هذه الحزمة تحوّل وصف المشروع إلى قرارات هندسية وخطط أسبوعية ومعايير قبول.

## القرارات الأربعة الكبرى (ملخص)

1. **Modular Monolith داخل EAR** — وليس ميكروسيرفس. كل وحدة منطقية مستقلة، لكن المعاملات موحدة.
2. **PostgreSQL هو الحقيقة النهائية** — القيود (Exclusion Constraints) تمنع التعارض، وليس جافا وحدها.
3. **Outbox + JMS + MDB** — الإشعار لا يُفقد، والنتيجة الطبية تُحفظ حتى لو تعطل الوسيط.
4. **الذكاء تشغيلي لا سريري** — قواعد وإحصاءات قابلة للتفسير، ولا تشخيص ولا قرار علاجي آلي.

## حالة الجهاز — ملخص سريع

| العنصر | المكتشف | الملاحظة |
|--------|---------|----------|
| JDK | 17.0.12 | `JAVA_HOME` غير مضبوط |
| NetBeans | 21 | موجود في `C:\Program Files\NetBeans-21` |
| GlassFish | **7.0.23** | موجود في `C:\server\glassfish-7.0.23` — **ليس 8.0.5** |

| Node/npm | 26.4.0 / 11.17.0 | جاهز لـ React |
| Git | 2.55.0 | جاهز |

> ⚠️ **أهم ملاحظة:** مشروعك مكتوب أنه Jakarta EE 11 + GlassFish 8، لكن المثبت فعلياً هو **GlassFish 7.0.23** الذي يطبق **Jakarta EE 10**. هذا ليس خطأً قاتلاً، لكن يجب حسمه في اليوم الأول. التفاصيل والحلول في `01-ENVIRONMENT.md`.

## كيف نعمل؟

- **أسبوعياً:** Sprint مدته أسبوعان، تسليم قابل للتشغيل، عرض 10 دقائق، وtag في Git.
- **لكل ميزة:** قصة مستخدم + معايير قبول + تصميم API + اختبار + تدقيق.
- **قاعدة ذهبية:** لا تُعتبر الوحدة مكتملة لأن الشاشة تعمل؛ تُعتبر مكتملة عندما تنجح **سيناريوهات الفشل والتزامن والصلاحيات**.
